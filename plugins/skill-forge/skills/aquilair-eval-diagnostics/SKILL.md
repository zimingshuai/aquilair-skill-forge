# Aquilair 评估失败自诊断（元技能）

> skill 工厂「迭代端」零件：评估失败 → 自动归因 → 反哺铁律，形成闭环。
> 本技能只做归因诊断，**不用于直接跑评估**（运行协议见 `evals/README.md`）。

## 一、触发与输入物定位

**触发**：评估回归结果出现 FAIL（结果矩阵判定非全 PASS），或人审怀疑某用例被误判（含疑似假阳性/假阴性）。

四层输入物（按序定位，全部只读，不得改动）：

| 层 | 路径 | 用途 |
| --- | --- | --- |
| ① 评估报告 | `evals/runs/*.md` | 读「结果矩阵」表（列：用例\|类型\|关键验证点\|判定），筛出 FAIL/可疑用例 |
| ② 轨迹落盘 | `evals/runs/transcripts/<日期-轮次>.json` | 每用例多次采样的 reply 与 tool_calls 原始轨迹 |
| ③ 用例定义 | `evals/<目标技能名>/cases.yaml` | 字段 id/type/user_message/expected/source/assert |
| ④ 目标技能 | `plugins/<插件>/skills/<目标技能名>/SKILL.md` 及 references/（业务技能在 business-hub、元技能在 skill-forge） | 铁律条款——归因对照物（现场读取） |

transcripts 读取规则（领域无关）：

- **key 规则**：`<case_id>-r<N>`，N 为采样轮次（通常 1..3）；同一 case 的全部 key 即该用例采样全集。
- **meta 快筛法**：先读各 key 的 `meta.pass`（布尔）快速定位失败采样；`meta.case_type` 判断用例权重（零容忍类优先处理）。
- **phase 语义**：phase 标注的是**调用发生时机**，不是工具属性——同一工具可在不同 phase 出现：
  - `none`：纯只读轮次，无确认卡环节；
  - `before_card`：确认卡之前——只应出现只读查询、建沙箱等准备性动作；
  - `after_confirm`：用户确认之后——confirm/execute/写后回查应落此段。
  - 核心判别点：**写/执行类工具调用若出现在 `before_card` 段，即违反「确认卡在写操作前」纪律**。

## 二、归因流程（五步）

1. **筛 FAIL**：读报告结果矩阵，判定列非「N/N ✅」者（如 ⚠️、❌、n/m）为失败用例；人审另有可疑用例则一并纳入。
2. **取轨迹**：对每个失败用例，取其全部 `<case_id>-r<N>` 采样，读 reply 与 tool_calls 序列（含 phase），观察写操作位置、读取顺序、是否重复拉取。
3. **逐条核对**：先对照 cases.yaml 的 expected（人工判定权威）与 assert（断言草稿），再打开目标技能 SKILL.md（含 references/ 按需加载），把 expected 中每条要求映射到具体铁律条款逐条核对。
4. **定类**：按第三节分类学归入 A/B/C/D 恰好其一；多因并存时列主因并说明次因。
5. **反哺**：按该类行动出口给落地建议——改哪个章节哪条措辞 / 加哪条用例 / 开工单附什么证据 / 断言怎么改。

## 三、归因分类学（恰好四类，不增不减）

| 类 | 名称 | 判定特征 | 行动出口 |
| --- | --- | --- | --- |
| A | 技能文档缺陷 | SKILL.md 缺对应铁律，或铁律措辞歧义可作两解，导致行为偏离 | 改目标技能 SKILL.md：补条款或消歧义 |
| B | 模型未遵守 | 铁律明确存在且无歧义，轨迹显示执行没走（有法不依） | 用例加权 / 提示词强化 / 换模型回归 |
| C | 数据或 MCP 问题 | 元数据错、底层数据脏、工具返回异常或超时，行为合规但结论被带偏 | 开工单给数据团队（附证据） |
| D | 断言口径问题 | 行为实际合规，expected/assert 本身误判（把对的判成错的） | 修断言与用例 |

**边界**：四类均不匹配时即为「证据不足」——回到第四节流程声明缺失输入，不得硬套最接近的类别。

## 四、证据规范

每个归因结论必须引用以下三类证据**之一以上**，否则降级为「待查」：

1. **transcript key**：如 `<case_id>-r2`（精确到采样轮次）；
2. **工具调用序列**：tool + phase 组合（如「execute 类调用落在 before_card 段」）；
3. **SKILL.md 章节定位**：目标技能的具体章节/条款编号（如「§六 边界说明」）。

- 禁止无证据推断；禁止引用未实际读过的文件内容。
- 证据不足时：如实输出「证据不足，还需要以下输入」，逐项列出（缺哪份轨迹、哪条元数据、哪个工具返回原文）。

## 五、输出模板

````markdown
# 失败归因：<日期-轮次>（目标技能：<技能名>）

## 失败用例清单
| 用例 | 类型 | 报告判定 | 失败采样明细（key） |

## 逐例归因
### <case_id>（<type>）
- 结论类别：A / B / C / D 之一（多因时列主因）
- 证据：① …（三类证据之一以上）② …
- 建议：…（对应该类行动出口的落地动作）

## 汇总
- 分类计数：A×n、B×n、C×n、D×n
- 反哺行动清单：□ 改文档 … ／ □ 加用例 … ／ □ 开工单 … ／ □ 修断言 …
````

## 六、泛化声明

本技能不含任何具体技能的铁律内容——fnb/mfg/ddl 及未来任何新技能的铁律，一律在归因时**现场读取目标技能的 SKILL.md 及 references/**（仓库内位于 `plugins/<插件>/skills/<技能名>/`，业务技能在 business-hub、元技能在 skill-forge）获得。归因分类、流程、证据规范与输出模板全部领域无关；新技能接入 `evals/` 目录后本技能自动适用，无需修改本技能。
