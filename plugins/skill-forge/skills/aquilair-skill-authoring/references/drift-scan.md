# 漂移扫描工序（runtime 更新 → 技能同步）

> 定位：runtime（本体平台 + MCP 网关）版本变更后的**例行运维工序**——六步流水线之外的独立入口，不重跑流水线。已获用户裁决固化（2026-11-20）；实例锚定同日 dev runtime 更新全流程。
> 消费者：总监工（探测与验收）+ 业务锻造师（技能同步实施）。文档自包含，按工序走零口头交接。

## 触发条件（任一即启动）

1. **dev 连接器 tools/list 对比发现 schema 变化**——工具 description/参数 schema 与上次扫描存档不一致（工具自描述已是方言一等参考，schema 变化即方言变化的先导信号）；
2. **平台发版通知**（新版本号、新能力公告、行为修复）；
3. 业务问答中出现**未记载的新错误形态或新行为**（被动触发——按「发现一处矛盾=一类问题须全量清零」纪律，顺带全量扫描）。

## 六步流程

| 步 | 动作 | 产出物 | 纪律点 |
| --- | --- | --- | --- |
| ① schema 对比 | 加载 dev 连接器全部工具，对比 description/参数 schema 与技能 facts 方言记载 | 漂移清单（新增/变更/移除/矛盾四类） | 只列不判——能力结论留给实测 |
| ② 语法实测 | 每项新能力构造最小调用验证语法（空集/0 条也证明语法通过） | 语法级证据 | 空集≠语法错；区分「语法过但数据空」与「被拒」 |
| ③ 正例实测 | 找真实数据验证非空返回（link code 现查 objects_links，不猜属性名——42201 纪律） | 正例证据（含条数） | **语法过≠可用**；正例通过才可进技能主路径 |
| ④ facts 修订 | 方言表重写：新能力入表带证据分级【正例已验/语法已验/仅 schema 声明】；缺陷表结案/新增；矛盾如实记录不下结论 | facts.md 更新 | 证据分级强制；「修复即删」；判定漂移标「待观察」 |
| ⑤ 锻造师同步 | 出工作令派业务锻造师改技能（SKILL 工具表/工作流纪律联动、版本 bump）——**只在测试区（hub-dev），发版区回流须用户显式发起** | 技能新版本 | 工作令要求锻造师**汇报工作令外的额外漂移**（11-20 实例：锻造师发现 3 条清单外漂移） |
| ⑥ 总监工验收 | 亲自复跑关键正例（不信子代理汇报）+ grep 旧表述残留 + git 范围检查（防越权改动与临时文件残留） | 验收结论 + 北极星对账 | 复跑用更强正例更佳；临时目录清理前查内容归属（防误删并行会话文件） |

## 实例锚定：2026-11-20 dev runtime 更新全流程

**背景**：workspace 01a19ac6（新品上市POC-最新版）随平台更新，dev 连接器 schema 出现新形态（用户指令「runtime 更新了，先用业务锻造师修改 launch-dynamic-assurance 然后再给我评估」）。

**①-③ 探测与实测结果**（总监工亲测）：

| 漂移 | 证据 | 分级 |
| --- | --- | --- |
| 排序可用：`order_by={"fields":[{property,direction}]}` | LaunchSystem 实测返回成功 | 正例已验（锻造师复验 demand_qty desc 严格降序+分页协同） |
| ObjectSet DSL 扩容：searchAround / static / union / intersect / subtract 节点；between / isNull / isNotNull / containsAllTerms 算子；page_size cap 100（101 报 42200） | 语法实测+锻造师正例（searchAround 双方向：FSD→MaterialDemand 全量起点 145 条、MaterialDemand→MIW n:1；union 去重、subtract 29−1、between 上界含） | 正例已验 |
| 数据工具 description 补齐（方言一等参考=自描述） | 工具加载即见 | — |
| 规则+属性 description 语义注解落地（DII/缺口量公式入元数据） | list_rules+neighborhood 实测 | — |
| **containsAnyTerm/containsAllTerms 被 searchable 门槛卡死**（老算子新限制，本项目全文检索暂无可用面） | 42201「未标记为可搜索」 | 能力收紧，入坑典 |
| 发布态判据矛盾（updatedAt>publishedAt 但 status=published，全平台同刻批量触碰痕迹） | list_workspaces | 待观察，如实记录 |
| 动作计数口径不一：list_actions(19) vs workspace_model(22) | 两接口实测 | 待澄清 |

**④⑤ 产出**：技能 v0.3.2（facts 方言节重写+坑典降级定位+TK-排序 结案+SKILL 工具行更新）；锻造师额外发现 3 条清单外漂移（全文检索门槛、2 个通知动作 content 模板缺 `$` 前缀→平台工单、42201 双义）。

**⑥ 验收**：总监工复跑 order_by 降序+searchAround 全量 145 条（强于锻造师正例）全过；grep 无「排序不可用」残留；改动范围仅两文件。

**证伪案例（教训）**：总监工初判「validation 规则类型存在」为**推断错误**——实测 ruleType 仅 calculation(43)+trigger(10)，无 validation。**推断一律不算证据，能力论断必须实测**（呼应 [[drift-needs-live-mcp-verification]]）。

## 教训清单（实例沉淀）

1. **推断≠实测**：schema 描述说「calculation/trigger/validation」≠本项目有 validation 实例——工具描述讲的是类型体系，实例分布要现查。
2. **工作令要求汇报额外漂移**：锻造师在实施中会撞见清单外漂移（本次 3 条）——工作令明确「汇报你发现而我清单未列的漂移」，白捡的探测面。
3. **临时文件清理先查归属**：仓根 `.tmp*` 目录可能是并行会话活文件（本例误删 np009 spec，幸可由元数据重建）——清理前看内容与时间戳，不确定就问。
4. **验收复跑选更强正例**：全量起点（145 条）优于单实例（5 条）——同成本更强证据。
5. **回流纪律**：技能同步只落测试区（hub-dev）；发版区（business-hub）改动须用户显式发起。

## 联动

- **facts 证据分级**：【正例已验/语法已验/仅 schema 声明】三档——分级写入方言表，未到正例的能力不进 SKILL 主路径；
- **工单流转**：扫描发现的平台缺陷（如通知模板缺 `$` 前缀）按工单模板移交平台方，不塞进技能文档；
