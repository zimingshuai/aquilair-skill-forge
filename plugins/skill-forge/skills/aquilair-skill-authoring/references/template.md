# SKILL.md 填空模板（第 4 步专用）

> 参照样板（均在 hub 仓 `aquilair-business-hub` 的 `plugins/business-hub/skills/` 下，跨仓引用、勿在本仓找）：解释型看 `fnb-inventory-analysis/SKILL.md`，受控执行型看 `mfg-transfer-allocation/SKILL.md`，复合型（解释 + 受控执行，references 四层分层首个完整落地）看 `launch-readiness-diagnosis/SKILL.md`。

## 目录结构约定

```text
<skill-name>/
├── SKILL.md          # 必需：核心指令（工具、探查循环、铁律、流程），50~120 行
├── references/       # 按需加载，分层承载：接口行为手册 / 业务语义卡 / 场景剧本 / 交付细化
├── scripts/          # save_meta / fetch_meta 等可执行助手（有元数据服务时必配）
├── evals/            # 标准双件：evals.json + trigger-queries.json（agentskills.io 规范，见下节）
└── assets/           # 模板、夹具等静态资源（目前各技能尚未用到，预留）
```

## frontmatter 模板

```yaml
---
```

### description 写作规范（唯一触发入口，三原则）

1. **主动一点**：模型天然欠触发，触发关键词宁可多列（同义说法、口语说法都放进去），不要指望模型「猜到」该用技能。
2. **中英混合句式**：中文触发词用「Use when the user asks about …」枚举，英文关键词用「any question about …」兜底——参照 fnb / mfg 现行写法。
3. **负向边界**：误触发一律用「not for …」句式治（写在 description 尾部 + 正文定位段重复一句），不用保守措辞治。

## scripts/（结合 MCP 的技能标配，双架构按场景选）

凡实测发现 agent 将重复执行的模式（元数据预取 / DSL 构造 / 数据校验）即固化脚本。两种架构按运行场景二选一：

- **首选：存档架构（save_meta 模式）**——数据由模型经宿主 MCP 连接器调用 `metadata_*` 获取（天然带宿主 OAuth 授权），脚本零凭证零网络，只做校验 / 固化 / 规范化落 `.meta-cache/`。适用 = 宿主已连 MCP 的常态运行；样板 = launch-dynamic-assurance/scripts/save_meta.py。
- **兜底：直连架构（fetch_meta 模式）**——脚本自带 `--token` 参数化直连网关批量预取（`--service / --workspace / --token / --refresh`，+ 可选 `--url` 兜底）。适用 = 宿主无 MCP 会话 / CI 批量 / 首装预热；母版 = fnb v2.0.0。
- **选择判据**：常态用存档（凭证不落脚本层）；无人值守批量才直连（token 只从环境变量 `AQUILAIR_MCP_TOKEN` 或参数传入，不落盘不进日志）。

通用适配要点：

- 缓存落技能目录 `.meta-cache/`（运行时生成、入 `.gitignore`）；空清单容错占位（如算法清单空数组写占位说明，不报错）。
- **SKILL.md 必须列「可用脚本」入口节**（提及文件名与用途——lint C13 查孤儿脚本）；脚本定位为非必需缓存刷新器，缓存与实时冲突以实时为准。

## agent-friendly 脚本设计九条（agentskills.io using-scripts，scripts/ 全部脚本适用）

1. **禁交互式提示**（硬要求）：不用 `input()`/`Confirm` 等——agent 跑在非交互 shell，交互提示会挂死整轮调用。
2. **`--help` 即接口文档**：描述 + 全部 flags + 使用示例，简洁可照抄。
3. **错误消息三要素**：错在哪 / 期望什么 / 建议试什么。
4. **结构化输出**：stdout 只放数据、stderr 放诊断，调用方（模型）可分别消费。
5. **幂等可重试**：重复执行无副作用（create-if-not-exists，不重复追加）。
6. **输入约束枚举**：合法取值写死并拒绝歧义输入，不猜调用方意图。
7. **危险操作给 `--dry-run`**：先展示将做什么，确认后再实做。
8. **退出码有语义并文档化**：0 成功 / 1 失败等在 docstring 声明，供调用方分支。
9. **输出尺寸可预测**：宿主对工具输出有 10~30K 截断——超限默认输出摘要，或给 `--output` 落文件再报路径。

## evals/ 标准双件（agentskills.io 规范，随技能目录分发）

- `evals/evals.json`：标准格式 `{skill_name, evals: [{id, prompt, expected_output, files?, assertions[]}]}`；**assertions 拆解要点**——从 expected 拆 2~4 条可验证句（含/不含什么、来源约束、顺序约束），禁「回答得好」类模糊断言。
- `evals/trigger-queries.json`：正负例各 10 条（`query / should_trigger / note` 结构）；正例须含**不点名域变体**（「六类齐套搞好了没」式，检验 description pushy 句式）；负例以 **near-miss** 为主（开发任务 / 邻域技能问法 / 边界任务），不用明显无关的凑数。
- **与目标仓 `evals/<技能名>/cases.yaml` 的关系**：cases.yaml = 产线权威（回归套件入口），技能内双件 = 随技能分发的标准格式（技能离仓仍可评估）；两件**同 PR 双向同步**，任一侧改动须同步另一侧。

## references 分层标准（第 2 步产物的形态约束，2026-10-30 定标）

- **接口行为手册**（facts.md）：DSL 语法最终版、工具行为、服务状态与能力边界、元数据缺陷、脏数据**模式**（模式级 + 挂工单 + 修复即删）。**禁止**数据实态快照（数值/条数/状态/回写与否）与时间戳日志章节——实测原始记录落目标仓 `evals/runs/`。
- **业务语义卡**（domain-model.md）：只载元数据查不到的业务文档编译（业务链/判定链语义/决策枚举/编码字典/规则公式口径）；实体/属性/关系/规则清单不维护副本（实时 `metadata_list_*` 为唯一权威）。
- 稳态 = 剧本（playbook）+ 交付细化（delivery）+ 接口行为手册 + 业务语义卡，四件小而稳，全部不随数据量与时间线性增长。

## 写作风格四条（写每一段前对照）

1. **祈使句**：直接说「读 X 再做 Y」，不写「你应该考虑读 X」。
2. **铁律配 why**：每条铁律带上根因或后果（「必须 X，否则 Y」）。发现自己在一遍遍加粗、全大写强调时，通常是规则没讲清而不是不够响——回头补解释，不加音量。
3. **例子胜过规则**：凡要求特定输出格式（表格列、确认卡、名称展示「中文名称（编码）」），放一个字面示例，让模型照抄结构而不是猜。
4. **行数预算**：SKILL.md 全文 50~120 行；超预算先问「这段是每次都需要，还是特定场景才需要」——后者拆 references，在「按需加载」节写清触发条件。
