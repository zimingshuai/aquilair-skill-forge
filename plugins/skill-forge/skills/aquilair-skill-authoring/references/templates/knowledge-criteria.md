# 知识取舍判据卡（建技能 / 改技能时逐条对照）

> 判据一句话：**推理错误是响的，口径错误是静默的**——路径推错了会吃到 42201/40401 立即修正（代价一次调用）；单位/口径算错了不报错、数直接错且看着合理。所以打法交给模型推理（错了会响），口径必须落档（错了不响）。

## 一、逐条判据（通式）

对 refs 与 SKILL.md 的**每一句**问：**删掉它，模型靠实时元数据、工具自描述和自己的推理，能不能得到同样正确的结果？** 能就删，不能才留。第二节的三问决定「知识放哪」，本节通式决定「要不要写」。

## 二、三类知识三去处

| 性质 | 例子 | 模型能推理出来吗 | 去处 |
| --- | --- | --- | --- |
| **打法**（场景组织、步骤顺序、判定面清单） | 「风险识别四路汇总」「业务链五环节顺序」「先查 A 再查 B」 | **能**——沿元数据现查推导：关系定路径、规则定判定面（注册规则输入并集）、动作定验证出口 | **不落档**（写了就是模板遮蔽：模型照模板取证而非按规则推导，规则集变化时模板过期且不自适应） |
| **接口行为事实**（服务端怎么响应） | 排序不可用、totalCount 是字符串、发布清数据、字段实名漂移、错误码形态 | **不能**——服务端行为不是逻辑推理对象，第一次必踩 | `references/facts.md`（坑典：模式级+挂工单+修复即删） |
| **口径陷阱**（字段直觉语义 ≠ 实际业务口径） | 单位差 5000 倍、两字段相加重复计入、目标三值不同源 | **不能**——字段名和描述推不出「不能相加」，直觉推理恰好翻车 | `references/calibers.md`（口径手册） |

三问操作化：①能从实时元数据推导吗？→ 能＝打法，不落档；②不能——是「服务端会怎么响应」吗？→ 是＝接口坑，进 facts；③不能——是「这个数 / 字段实际怎么算才对」吗？→ 是＝口径陷阱，进 calibers。

## 三、能删的五类（对上就删）

| 类 | 判别 | 例子 |
| --- | --- | --- |
| 实时元数据里就有 | 现查 `metadata_*` 即得 | 实体属性清单、动作清单与编号、规则描述里已自带完整公式的规则公式 |
| 工具自描述 / 参数 schema 里就有 | 宿主工具定义已写明 | 动作返回形态、幂等键用法、分支缺省值、写入工具调用形态、入参名清单 |
| SKILL.md 已有同样纪律 | refs 复述主文件的铁律 / 流程 | 「数据实态现查」「不代算」「不猜字段名」 |
| 常识，或读数据自然能看出 | 看到行数据即可理解，无需预先告知 | 主键前缀长什么样、返回里有哪些字段 |
| 元叙述 | 写给维护者 / 开发者看，模型现场用不上 | 手册维护纪律、给界面开发者的备注、重复多遍的同一句出处、实测日期 |

## 四、必须留的两类

- **推理不出的服务端行为**：查询方言、必填与键名规则、透明补链行数、错误码处置。
- **错了不响的口径陷阱**：单位口径、分环节回填的空值、易读错的字段。

**边界**：写操作纪律（确认卡 / 不代算 / 不拍板）不以「模型自己会判断」为由删——那是约束发挥，不是知识。

## 五、删除的四条执行纪律（踩坑换来的）

1. **「已有载体」要指得出原句**：说「SKILL.md 已有」「自描述里有」，必须能在对应文件里指出那句原文；指不出就不算已有。
2. **「自描述里有」要在该技能绑定的环境里核实**：两个 MCP 环境的服务版本不同步——测试区连接器的 `objects_query` 有完整方言自描述，发版环境连接器的同一工具自描述为空、只有参数 schema（2026-11-24 实测）。按「自描述有」删方言之前，先在该环境看一眼工具定义。
3. **「常识可得」从严**：有实测证据的坑不因「看起来像常识」而删——实测说明它真的发生过（浮点尾数、某列恒为空、分配行没有日期列）。判不准就留着：多一句话的代价远小于一个静默的错误。
4. **删后必须独立复核**：先留快照 → 逐句对比列出全部消失的条目 → 逐条判 → 交没参与删除的一方复核。实证：极米技能第二轮清理 189 处删除，约 11 处删后无载体（以为主文件已覆盖、或判成了常识），是另一方复核才发现的；自己删自己核发现不了。

## 六、出处与证据标注（巡检锚点，可减不可删）

- refs **至少一处**「来源：」或「出处」标注（lint C10，也是人工巡检「过时论断」的溯源依据）；同源的多条出处合并成文件头一行即可，不删尽。
- 实测证据**留现象、去日期**：写实测到的现象（「某列对未变化的物料恒为空」），不写「某日实测」；只有行为随版本变化时才写明版本或日期。

## 七、附带裁决（同源，一并遵守）

- **交付模板可靠，推理不用模板**：输出骨架/确认卡格式用模板（稳定性）；判定面/取证路径一律从实时元数据推导——技能内不保留任何可从元数据推导的清单快照
- **快照即漂移源**：枚举值清单/规则编号/动作计数/实体属性副本一律不维护，实时 `metadata_list_*` 为唯一权威（实测数字可作 facts 证据引用，不作清单维护）
- **公式缓存看元数据自足程度**：calibers 可缓存判定公式——价值在响应速度，以及规则文本与业务文档可能不一致时的对照。只有规则描述已自带完整公式与业务注解时才按通式删；描述缺公式、缺单位口径、或需要与业务文档对照的公式缓存保留
- **「某表没有某列」是坑不是清单**：锚点字段名本身可现查，但「这张表没有 direction 列」「这列恒为空」属于模型查不到就会踩的静默坑，留在 facts
- SKILL.md 只写**模式级**规则（50~120 行），字段名下沉 refs（字段名=漂移点）
- **未知出口**是收口机制不是特判清单：未知→沿依赖链（结论字段→sourceRuleCode→规则输入面）找区分性证据→元数据穷尽且有动作承载→诊断型确认卡（沙箱优先/回查点预定义/结果回填原结论）
