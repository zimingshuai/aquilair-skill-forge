# 域知识摄取（ingest）工作流剧本

> 本文件是 `aquilair-knowledge-wiki`（域知识库技能）的主剧本：用户带着**文档包 + MCP 地址**进厂时，LLM 按本剧本自主完成知识摄取与编译，产出结构化域知识库——新技能开发时经 `aquilair-skill-authoring` 第 2 步协同调用；存量域再摄取时驱动迭代（见文末「再摄取与迭代联动」）。设计思想源自 Karpathy LLM Wiki 的 ingest 循环（调研背景见仓库 `aquilair-knowledge/research/2026-09-28-llm-wiki-karpathy.md`）。

## 一、定位与人机分工

- **执行者**：装配本技能的开发会话（LLM），无需任何新基础设施——纯 markdown 文件工程。
- **LLM 拥有**：`aquilair-knowledge/sources/<域名>/` 知识库区（摄取、编译、更新）。
- **LLM 不得直改**：`plugins/*/skills/` 技能资产——知识库到技能的转化必须走六步流水线与验收，禁止「ingest 顺手把 SKILL.md 也改了」绕过回归。
- **人裁定**：分类存疑文档、立项决策、草稿转正（对齐 eval-generator「只懂结构不懂业务，人工复核转正」纪律）。

## 二、五步摄取流程

### 1. 文档分类入库

先按来源把文档拿到本地，再逐份读（业务文档、操作手册、调研报告等），判类型与所属域 → 原样复制入 `aquilair-knowledge/sources/<域名>/raw/`（保留原名原格式）→ 生成**源摘要页**（每文档一节：类型、核心要点、可用于技能开发的口径/场景线索）。分类存疑的标「待人工裁定」，不强行归档。

**文档获取通道（按来源分流）**：

- **飞书链接**：默认高频源。宿主装有 lark-cli 时（ZCode 已装）直接拉取——`lark-cli docs +fetch --doc "<url>" --doc-format markdown` 取正文，文档内图片按 `feishu.cn/file/<token>` 提取 token 后用 `docs +media-download` 逐张落盘；**不走 webReader/WebFetch 抓飞书**（需登录的文档必碰登录墙，这是默认规则不是碰壁后的补救）。未装 lark-cli 的宿主：请用户从飞书导出文档（Word/PDF）后上传，不硬抓。
- **本地/上传文件**：直接读取，无获取动作。

### 2. MCP 遍历提取

- 机器半步：跑该域 `scripts/fetch_meta.py` 拉 `get_meta_objects` / `get_meta_rules` / `get_meta_actions` 落盘 `.meta-cache/`。
- LLM 半步：通读缓存，编译**实体与动作摘要页**（每实体：展示名、主键、关键字段与中文释义；每动作：参数、读写属性、准入规则），标注「此为元数据级遍历，未经调用验证」。

### 3. 实测探针（铁律的唯一来源，不可跳过）

真实调用代表性工具做探针：**只读工具直接实调**（filter 语法试探、返回结构记录、脏数据发现）；**写动作类工具禁止实调**（生产数据红线——只从元数据记录参数契约，验证留到第 6 步护栏题与沙箱）。逐项记**事实卡片**：参数坑、filter 语法、读写划分、返回结构、脏数据。元数据遍历（第 2 步）不能替代本步——「缓存和文档看看就够了」是反合理化表格明令禁止的借口。

事实卡片**两级去向**（教训要放在模型必读处，不是埋在按需加载的深处）：

- **工具级坑**（参数形态、调用陷阱——每次用该工具都相关）→ 目标技能 SKILL.md 的工具区一行提示，触发即全文加载、模型必读；
- **领域口径**（KPI 边界、字段释义、数据脏区——特定场景才相关）→ 目标技能 `references/`（出处标注必带）+ 域知识库编译层。

### 4. 编译域知识页

| 页面 | 内容 | 消费方 |
| --- | --- | --- |
| `glossary.md` | 域术语表：术语、实体英文名、同义词/口语说法、弃用叫法 | lint 术语一致性检查、出题措辞参考 |
| `index.md` | 知识页索引：raw 文档、摘要页、事实卡片、缓存位置 | 溯源导航 |
| `log.md` | 摄取日志：何时喂了什么、编译/更新了哪些页。**条目统一前缀** `## [YYYY-MM-DD] 类型 | 标题`（类型：ingest/query/lint/re-ingest），可被 `grep "^## \[" log.md` 直接解析 | lint「过时检查」与再摄取程序化对照的变更依据 |

### 5. 联动流水线

- 新域：第 1 步立项三条件与四问的证据从知识页取（文档里的重复场景、需约束行为、MCP 工具清单）；第 2 步铁律原料从事实卡片取。
- 产出仅是**草稿状态**，人工复核转正后才可进入第 4 步模板填空。

## 三、再摄取与迭代联动（插件升级优化的引擎）

新文档入厂或 MCP 服务版本变更时，对存量域执行再摄取：

1. 新旧对照：新源摘要 vs 既有知识页，凡引用旧源的条目列**过时候审清单**（依据：references 出处标注 + `log.md` 变更记录）。
2. 候审清单人工裁定后，涉及技能口径的改动走「第 4 步增量改 → 第 6 步全量回归」。
3. 跑 `python tools/lint_skills.py` 验证接线与结构无回归。

## 四、产物目录结构

```
aquilair-knowledge/sources/<域名>/
  README.md          # 域说明与存量声明（人工维护）
  raw/               # 业务方原始文档（AI 只读，保留原格式）
  glossary.md        # 术语表（LLM 编译）
  index.md           # 知识页索引（LLM 编译，query 检索入口）
  log.md             # 摄取/变更日志（LLM 追加，可机读前缀格式）
  analyses/          # query 好答案归档的分析页（探索复利）
```

示范样板：`aquilair-knowledge/sources/mfg/`（2026-09-28 首次编译，glossary 从 `.meta-cache` 提取）。
